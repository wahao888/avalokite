## 敘事策略

1. **前三秒是「你的 LINE 又響了」，不是品牌。** 鎖定畫面、通知一則一則跳出來、手機在震——每個開店的人都認得這個畫面，所以不用解釋。
2. **痛點只講一個：晚回，客人就走了。** 時鐘從 23:30 捲到隔天 08:45，最後一則通知是「沒關係，我先找別家了」，時間戳是凌晨 1:12。
3. **每個特點一個畫面、一句話。** 字交給字幕，畫面只留一個大標：秒回／24H／用你的資料回答／報價不會算錯／真人接手 AI 讓開。
4. **特點全部來自產品的真實行為**，沒有一句是形容詞：知識庫有出處、資料沒有的會說不確定、價格由系統帶入不讓模型加總、轉真人後 AI 靜音並通知。
5. **收在別人給不出來的證據：** 我們自己的官方 LINE 就是這一套，所以 CTA 不是「了解更多」，是「加 LINE，親自考考它」。

## 聲音

- **旁白**：Microsoft Edge 線上神經語音 `zh-TW-HsiaoChenNeural`（台灣口音女聲），語速 +6%。想換聲音：`VOICE=zh-TW-YunJheNeural`（男聲）或 `zh-TW-HsiaoYuNeural`（另一位女聲）重跑即可。要用真人配音，把檔案放進 `build/vo/` 取代同名 mp3，跳過 `make-vo.py`。
- **配樂**：程式合成、104 BPM、C–G–Am–F。不是現成曲子，不會被 IG 的版權偵測靜音。第 1 幕只有低音與時鐘滴答；第 2 幕鼓進來；第 7 幕把鼓抽掉讓那一句有空間；第 8 幕全部回來並收在主和弦。
- **音效**：通知聲＋震動、訊息泡泡、打勾、蓋章、上鎖、轉場——時間點寫在 `reel.html` 的 `data-sfx` 上，跟畫面是同一個來源。
- **響度**：成品 -14 LUFS；旁白約比配樂高 8–15 dB（有人說話時配樂自動退後）。

## 怎麼重新產出

```
cd build
pip install edge-tts numpy scipy        # 第一次才需要
npm i playwright                        # 第一次才需要（會沿用 ~/Library/Caches/ms-playwright 的瀏覽器）

python3 make-vo.py        # 錄旁白，並依旁白長度產生 timeline.json / timeline.js
node    render.js --sfx   # 從 reel.html 讀出音效時間表 → sfx.json
python3 make-bgm.py       # 合成配樂 bgm.wav 與音效 sfx.wav
python3 make-audio.py     # 旁白＋配樂＋音效 → audio.m4a（-14 LUFS）
node    render.js         # 逐幀截圖餵給 ffmpeg，混上 audio.m4a → ../line-ai-reel.mp4
```

改稿只要動 `make-vo.py` 裡的 `SCENES`：每一幕的長度、字幕、畫面對齊的時間點（`cues`）
都會跟著旁白重算，`reel.html` 裡用 `data-at="@cue名稱"` 對齊的動畫不用改。

檢查版面：`node render.js --shots 3,8.5,19.8` 會把指定秒數的畫面存到 `build/frames/`。

**成品裡的價格與 LINE ID 是寫死的**（`reel.html` 第 8 幕）：起價 NT$29,000 來自
`src/lib/products.ts` 的 `ai-chatbot-lite`，LINE ID 來自 `src/lib/site.ts`。調價後要重新渲染。
