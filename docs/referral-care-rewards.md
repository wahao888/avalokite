# 推薦碼與免費維護月份

## 使用流程

1. 正常付費、無欠費的維護客戶，在「訂單查詢 → 管理訂閱」按「取得我的邀請碼」。每個 Email 一組公開碼，與訂閱管理憑證完全分開。
2. 分享邀請連結。朋友開啟後，此分頁的結帳頁會帶入邀請碼，也可手動輸入。
3. 新客戶完成任一品項的真實付款，包括促銷保留金，雙方各核發一個免費維護月。付款失敗、模擬付款、金額不符及重送不會多發。
4. 每個新客戶以正規化 Email 與電話識別，限首次付費；同一客戶重複下單、續約、自行推薦不再核發。推薦人於付款成功時仍須有正常維護訂閱。
5. 月份綁定 Email，可累積；換卡、換方案不會消失。未訂閱維護者先保留，之後用同 Email 啟用維護即可安排使用。獎勵不延長原有最短承諾期。

## 安排實際免費月份

**獎勵自動核發；免扣款排程須人工在綠界安排。** 單純修改本網站日期不會阻止綠界照原排程扣款。

1. 營運後台 →「推薦獎勵」（`/admin/referrals`）查看未使用月份與有效維護訂閱。
2. 在綠界廠商後台確認訂閱及目前已付款期間，安排一個完整維護月不扣款，並確認後續恢復扣款日。不可使用「終止」來代替暫停，終止後無法重啟。
3. 在 Avalo 後台選擇對應訂閱，填免費維護起日與綠界操作核對紀錄；勾選已確認免扣與恢復排程，再登記。
4. 系統記錄 `[起日, 次月同日)` 的免費服務期間（台北時間，月底夾限至次月最後一天），通知客戶，並在訂閱管理頁顯示。例：1/31 起的非閏年免費月，2/28 起恢復付費。

登記端點要求管理員登入及同來源 POST；禁止使用他人訂閱、重複兌換及重疊免費期間。記錄兌換不會自行操作綠界、修改方案月費或綁約結束日。綠界操作必須先完成；客戶端也明示確認排程前仍依原訂閱扣款。若綠界商店尚無法調整所需排程，先保留獎勵，勿標記已兌換。

綠界依據：[定期定額訂單作業 API](https://developers.ecpay.com.tw/2900/) 僅支援補授權與終止，其餘變更需到廠商後台；[定期定額管理](https://support.ecpay.com.tw/16214/) 說明暫停、啟用及下一次執行日的操作。

付款通知信與獎勵信使用既有 SMTP；寄送失敗不回滾已入帳的付款／獎勵，也不把未寄出的信當成獎勵失效。後台與客戶查詢是獎勵紀錄的依據。退款目前沿用既有人工流程，會計處理退款時應一併核對相關推薦獎勵，沒有新增自動退款或獎勵撤銷。

## 部署與驗證

- 新增資料表 `ReferralCode`、`Referral`、`CareReward`，訂單新增 nullable `referralCode`；舊客戶與訂閱不回填、不改價。
- 部署前備份 SQLite，執行 `npx prisma generate`；套用 `npx prisma migrate deploy` 後才啟動新版應用。
- `tests/referral.test.ts` 使用獨立暫存 SQLite，驗證付款真實性、冪等、累積、保留、Email／電話防重複、月底日期與後台兌換權限。既有金流與訂閱測試一起執行。
- 尚未在正式環境用真實款項或綠界後台驗證免費月排程；不可把本機驗證解讀為已完成正式免扣款測試。
